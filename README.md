# DidactAI

DidactAI is a Romanian-language mathematics tutoring prototype for Moldovan middle- and high-school students. It presents a Romanian exercise bank in a Streamlit interface and combines predefined pedagogical content, transparent rules, and classifiers trained on exercise data.

This README describes the repository as it exists now. The answer-checking and neural-startup fixes, regression tests, and portfolio documentation in this revision are post-competition improvements; do not present them as features of the original competition build without evidence from that version.

## What Is Implemented

- Select exercises from the bank by domain and topic, or start a tutor exercise from a selected domain.
- Start with a general scaffold, then reveal stored solution steps in order. Reflective questions come from a predefined Romanian list; the final stored step can include the answer.
- Estimate mastery with a small rule-based update and recommend an exercise by domain and target difficulty. Candidate selection is a rule-based filter and sample, not an ML-ranked recommendation model.
- Classify exercise domains and difficulty with two saved scikit-learn models; the main demo displays their predictions.
- Optionally estimate a learner-state label with a saved neural model when TensorFlow is installed and the artifact loads.
- Keep interaction history and mastery in Streamlit session state; there is no user account or database-backed progress history.

Hints, reflective questions, diagnostic aggregation, mastery updates, and most recommendations use predefined content or pedagogical rules. The application does not use an LLM, generate original explanations, or grade arbitrary proofs.

## Machine-Learning Models

**Structured difficulty classifier.** A scikit-learn `RandomForestClassifier` predicts `Dificultate_group` (`1 - bază`, `2 - mediu`, `3 - consolidare`, `4 - avansat`). Inputs are 14 numeric features (`Itemul`, `Sursa_year`, problem/solution/answer lengths, digit and math-symbol counts, and indicators for percent, geometry, equations, radicals, functions, and real-life context) plus the categorical fields `Tema_norm`, `Domeniu`, and `Sursa_type`. The preprocessing pipeline imputes missing values, scales numeric features, and one-hot encodes categorical features.

**Problem-text domain classifier.** A TF-IDF vectorizer and `ComplementNB` predict `Domeniu` from the Romanian problem statement (`Problema`). This model classifies text; it does not generate or explain it.

**Optional neural learner-state classifier.** A feed-forward TensorFlow/Keras model predicts one of `autonomie_buna`, `blocaj`, `progres`, or `supraincarcare`. Its nine inputs are time spent, hint count, attempt count, correctness, mistake count, exercise difficulty, previous mastery, consecutive errors, and requested help level. The checked-in `data/processed/student_interactions.csv` has 2,200 synthetic rows. Its labels and features are generated by rules in `src/neural_student_state_model.py`; they are not real student records. Its saved metrics measure agreement with those synthetic labels, not learning gains or performance with real students.

The neural component can select a target difficulty from a fixed mapping of predicted states. The exercise itself is still chosen by domain/difficulty filtering and sampling.

## Datasets And Saved Metrics

The repository contains two distinct exercise datasets:

- `data/processed/exercises_processed.csv`: the legacy processed set, 489 rows; 477 have both topic and difficulty labels, and 51 rows repeat a normalized problem text.
- `data/processed/exercises_augmented.csv`: the augmented set, 1,344 rows; all 1,344 have topic and difficulty labels, and the saved evaluation report records zero repeated normalized problem texts.

The saved classifiers and `models/evaluation_report.json` correspond to the augmented set, not the 489-row legacy set. The metrics below are copied from that checked-in report; they are holdout classification metrics, not evidence of improved student learning.

| Task | Holdout | Baseline macro-F1 | Model macro-F1 | Model accuracy |
| --- | ---: | ---: | ---: | ---: |
| Structured difficulty, 1,344 source rows | 296 | 0.163 | 0.831 | 0.922 |
| Text domain, 1,265 rows after filtering | 279 | 0.078 | 0.974 | 0.982 |

`models/neural_student_state_report.json` reports accuracy 0.923 and macro-F1 0.914 on a 440-row test split from the 2,200-row synthetic dataset. These scores describe prediction of rule-generated labels only. The exercise classifiers also use a single train/test split and should be assessed on external data before making claims about generalization.

## Installation And Startup

The lightweight path was tested on Python 3.12.14. The project declares Python >=3.11; the Dockerfile uses Python 3.11 and was not executed in this audit.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements-light.txt
streamlit run app.py
```

Open the local URL printed by Streamlit (normally `http://localhost:8501`). The lightweight requirements omit TensorFlow; rule-based tutoring and the two scikit-learn classifiers remain available, while neural learner-state predictions are omitted.

To install the optional TensorFlow path instead, use `python -m pip install -r requirements.txt`. If TensorFlow is available but the neural model file is missing, startup attempts to train it from the interaction CSV, generating synthetic data if that CSV is also absent. This training behavior is not required for the lightweight path.

The app normally loads the checked-in models and augmented CSV. If required classical-model assets are absent, the report is invalid, or its dataset row count differs, `app.py` calls `train_all()`. That function rebuilds both processed CSVs from the raw workbooks and retrains the classical models, writing artifacts and reports. This fallback changes local files; keep a copy of any artifacts you want to preserve before triggering it.

Run the Docker path with `bash run_docker.sh`; it builds from `requirements.txt`, including TensorFlow. To run the regression suite:

```bash
python -m unittest discover -s tests -v
```

## Answer-Checking Scope

The current checker accepts a complete normalized exact match, or exact rational equivalence for supported scalar answers. Supported numbers include integers, signed values, fractions, decimal points, and Romanian decimal commas. For scalar comparisons, variable labels and recognized units must match; numeric unit conversion is not performed. Whitespace between separate tokens is preserved, and the checker never evaluates student input.

The checker returns `needs_review` for symbolic equivalence it cannot prove, multi-part responses, intervals/sets, free text, unsupported units, and ambiguous formats. A missing or malformed numeric key returns `invalid_key`; an empty response returns `no_answer`. These unverified results do not change mastery, mistake counts, neural predictions, or the session interaction log. General symbolic equivalence and proof grading are not supported.

## October 2026 Audit Revision

The augmented bank contains 132 source-derived rows and 1,212 rows labelled `Generat` in `Sursa`. An independent numerical-template audit matched all 1,212 generated answer keys; that does not establish that every prompt is unambiguous or pedagogically sound. The audit identified 42 source-derived rows and 17 generated savings prompts needing review. They remain in the training CSV, but `data/processed/exercise_review_flags.csv` excludes them from diagnostic, home, tutor and recommendation candidates. The available practice bank currently contains 1,285 rows. Removing a flag requires reviewing the original prompt, diagrams, answer format and solution.

The corrected tutor retains feedback and hints across reruns, advances with its next-exercise button, and prevents repeated grading of a completed attempt. Session statistics count evaluated attempts, not unique completed exercises. The mastery indicator is a global heuristic, not a calibrated probability or per-topic mastery model. The app only suggests a review date; it does not store a schedule or send reminders.

The October audit changes were prepared with AI assistance after the competition. Review and understand them before attributing any particular implementation decision to yourself. The model artifacts and original training CSVs were preserved. See `docs/audit_report.md`, `docs/audit_changes.md` and `docs/demo_guide.md` for the checks, limitations and recording instructions.

All lightweight functional tests passed; the optional TensorFlow startup unit test is skipped when TensorFlow is absent. Saved neural-network scores were reproduced independently using NumPy and the saved weights. Actual TensorFlow inference could not be verified in the audit environment: even basic TensorFlow addition aborted because process filesystem information was unavailable. Use `python diagnose.py --neural` on your own full installation before demonstrating that optional component.
